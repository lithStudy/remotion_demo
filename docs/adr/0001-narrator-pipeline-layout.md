# 口播管线采用稳定包名、Step 门面与能力域切分

口播视频生成代码将从版本化目录 `script_v6/` 迁入稳定目录 `narrator_pipeline/`，删除旧目录且不留长期兼容壳。编排改为包内函数调用加薄 CLI，不再用 subprocess 串步；对外仍暴露 Step0–4 门面与既有 `--start` / `--only` 心智，对内按能力域 `analysis` / `images` / `audio` / `codegen` / `contracts`（外加 `cli` 与顶层编排）组织。口播文案迁至仓库根 `narrations/`，与管线代码分离。本次明确不改动分镜脚本等对外契约语义，也不改动 Step1 的 AI 阶段逻辑与 prompt 文案——目标是可维护性，用结构清晰加行为回归双验收。

**Status:** accepted

## Considered Options

- **目录命名：** 保留 `script_v6` 内再建包 / 稳定名 `narrator_pipeline` / 另置 `tools/` 下再套壳 → 选稳定名，避免版本号进入架构路径。
- **编排：** 继续 subprocess + 独立脚本 / 包内调用 + 薄 CLI / 只留单一入口取消分步脚本 → 选包内调用，保留分步可跑。
- **切分原则：** 纯按 Step 目录 / 纯按能力域 / Step 门面 + 域实现 → 选混合，兼顾运维心智与代码边界。
- **媒体域：** 合并为 `media` / 拆成 `images` + `audio` → 选拆分，与 Step2/3 对齐；若日后共享逻辑变厚再抽小层。
- **旧目录：** 立即删除 / 短迁移壳 / 长期 shim → 选立即删除，避免双路径再次污染可维护性。
- **口播稿位置：** 包内子目录 / 仓库级 `narrations/` / 跟成片目录 / 本次不管 → 选仓库级内容区。

## Consequences

- 所有文档、技能与本地命令中的 `script_v6` 路径需一次性改完；不提供旧路径转发。
- 能力域比「四域合并 media」更细，初期可能有少量跨 `images`/`audio` 的重复工具函数，可接受。
- 回归时须区分「模型非确定性」与「程序侧契约被搬家改写」；后者失败即重构未完成。
